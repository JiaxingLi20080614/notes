1 · 诊断：慢和忘为什么是同一件事

你现在的动作是：看视频 → 他写一段 → 你暂停跟着敲一遍 → 继续。这个循环里，你的大脑在做的事情叫识别（recognition）——看到屏幕上有 int，你的手敲 int；看到 for，你敲 for。

但你考试、甚至是你以后真正写代码的时候，大脑要做的事情叫生成（recall）——面对一个空文件和一个问题，你得自己决定第一步写什么。

识别 ≠ 生成。能认出来，不代表能想起来。这就是为什么第二天全忘了——你当天压根没把它存进去。

顺带把这笔时间账算清楚

敲一段 20 行的代码大约花 5 分钟。但这 5 分钟里，真正让大脑参与决策的时间可能不到 30 秒，剩下 4 分半是手指在动。

所以你感觉「我今天学了 2 小时」，实际大脑只工作了 15 分钟。

结论：你不是写得慢，你是「低认知负荷地消耗了大量时间」。慢和忘是同一个原因——所以不需要两个解法，改一个动法，两边一起解。

还有一个必须提前说的事实

写代码的快慢，从来不是程序员的瓶颈。真正的瓶颈是两件事：从空白文件的构建速度，和调试的速度。

所以你焦虑「我太慢了」其实是焦虑错了地方。别追"敲得更快"，要追「每次动手指的时候，脑子也得跟着动」。

2 · 先给「跟着抄」平反

我不是说你一直在做无用功。跟着抄有三个真实价值：

  • 熟悉编译器的手感——报错长什么样、怎么编译怎么运行，这些东西只能靠亲手点一遍才知道
  • 消除「我写不出来」的恐惧——对零基础的人来说，敢打开 IDE 本身就是一道坎
  • 让眼睛习惯代码的形状——缩进、括号配对的视觉模式

这三点对一个新手是有价值的，但它不该承担「记住」的任务。

正确定位：跟着抄是热身，不是训练。把它从一个小时的流水线，压缩成每天 10 分钟的开场，剩下的时间给下面三个模式。

3 · 怎么变快：三种模式

模式 1 · 延迟复现 最有效，也最不舒服

做法：鹏哥在动手写代码之前，通常会先说「我现在要做什么」——就在这一刻暂停。不要等他写完。

1

自己先在编译器里写，目标是跑通。卡住至少硬撑 5 分钟再放弃。

2

播放看他怎么写，只回头看你卡住的那一段。

3

把他那段话用自己的方式重敲一遍，加一行注释：「我当时卡在哪」。

为什么反而更快：你只慢在自己不会的地方。会的地方一秒带过。
为什么记得住：你卡住的那一刻，大脑才真正在工作——而不在手。

模式 2 · 预测式 最省时间，适合长代码

做法：看到鹏哥写完 scanf("%d%d", &a, &b);，立刻暂停。

  • 先猜下一行是什么，甚至先猜这段跑出来输出什么。写纸上。
  • 然后再放。

猜对了 → 这一行你已经会了，跳过，不用敲。

猜错了 → 这就是你今天唯一要学的一行，重点记。

这个模式下，一集视频里你真正需要动手的代码可能只剩 3–5 处，其余全跳过。速度自然翻倍，而你学到的东西反而更准。

模式 3 · 抄改（不是抄写） 改动最小，从现有习惯升级

做法：照样跟着抄，但抄完之后必须做一处改动。

鹏哥写：求 1~100 中所有能被 3 整除的数的和
你抄完改成：求 1~100 中所有偶数的和        ← 有意义的变化 ✓
          把 sum 改成 total              ← 换变量名，无效 ✗
          把 100 改成 200                ← 换常数，几乎无效 ✗

为什么有效：要改对，你必须知道哪一行是干什么的。而你改错的地方，就是你自己以为懂了其实没懂的地方。它把「抄写」变成了一次强制的理解检验。

硬指标 · 20 分钟法则

一个 20 行以内的程序，从空白到跑通，新手 8–15 分钟是正常的。

超过 20 分钟还没跑通 → 不是你写得慢，是某个概念你根本没懂。这时候不应该死磕，应该：回去看那一集，或者直接问 AI——「这段代码我卡在 XX，只告诉我思路，不要给完整代码」。

这条判断标准比什么都重要：它把「我很笨/我太慢」的自我怀疑，转成了「我这里没懂」的具体问题。

4 · 怎么不忘：四个动作

先做一件减压的事：分清两种「忘」

忘的是什么例子要不要管
语法细节 double 用 %lf 还是 %f？判断相等是 == 还是 =？ 不用背查就行。写了十年代码的人也天天查。
问题 → 解法的骨架 判断整除写 n%3==0；遍历数组写 for(i=0;i<n;i++)；累加前先 int sum=0; 必须记住这才是要攻的。

C 语言真正需要刻进脑子里的东西，不超过 15 条。就是你笔记里那几张表：格式符表、ASCII 三组、运算符优先级、几个固定套路的骨架。

所以你说的「什么都忘了」，很可能 80% 是本来就不该背的。把记忆预算压在那 20% 上，负担立刻少一大半。

动作 1 · 注释只写「为什么」，不写「是什么」

// ✗ 无效注释（等于把代码翻译一遍，对记忆毫无帮助）
scanf(" %c", &x);   // 读入一个字符

// ✓ 有效注释（写的是「为什么这么写 / 不这么写会怎样」）
scanf(" %c", &x);   // %c 前必须加空格：否则会把上一次输入留下的回车读进来，x 变成 '\n'

这是成本最低、收益最高的一步。多花 30 秒，留存翻倍。它把「手指运动」强行变成了「语义加工」。

自检标准：如果你写完注释，发现自己只能写出「这是什么」、写不出「为什么这么写」——说明这一段你没懂。标红，回去看视频。这是整套方法里最好的「懂没懂探测器」。

动作 2 · 隔天重写，不要当天写三遍

这条你已经听我说过两次了——数学的「一题三遍法」、英语的检索练习、现在这个，是同一个东西的第三次出现：

遍次时间怎么做
第 1 遍今天跟着写 / 拼出来（这是输入）
第 2 遍明天凭记忆重写，不看视频不看笔记
第 3 遍3 天后还能写出来 → 这条真的进脑子了

关键是间隔，不是次数。当天连写三遍没用——那是短期记忆在硬撑，你会产生「我记住了」的错觉，然后第二天照样忘。

第 2 遍最值钱，因为它暴露的正是「你以为自己懂了」的那部分。

动作 3 · 建「最小代码库」，每天开工前跑旧的

你现在的文件大概还是散的。改成按「这段解决什么问题」来组织，不按「第几集」组织。

snippets/
  01_scanf_char.c        // %c 不跳过空白 —— 写给明天就会忘的自己看
  02_format_width.c      // %3d 域宽、%.1f 精度
  03_compound_assign.c   // b *= a += 2 的结合顺序
  04_divide_mod.c        // 整数除法 7/2=3、取余 %
  05_until_zero.c        // 读到 0 为止的统计（2025 真题）
  06_array_max.c         // 数组最大值及下标
  07_bubble_sort.c       // 冒泡排序

三条规则：

  1. 每个文件独立可编译、不超过 20 行，第一行注释写「这段解决什么问题」。
  2. 每天开始学新东西之前，先随手打开 1–2 个旧的，不看原文件重新敲一遍。
  3. 敲不出来 → 那就是今天要补的东西。

这每天 5 分钟的热身，就是「艾宾浩斯遗忘曲线」的穷人版实现——不需要做闪卡、不需要排复习计划，靠开工前两个文件就解决了。

动作 4 · 每天收工三行日志（3 分钟）

10/15
今天学的唯一一件新事：scanf 读 double 必须用 %lf，写成 %f 会读出乱码
卡住的地方：一直不懂为什么输出 48，后来发现 %c 读的是字符 '0' 的 ASCII 码
一句话总结：格式符必须和变量类型对应 —— 这是 printf/scanf 的全部秘密

为什么有用：明天开始前读一遍，一天的收获压成 3 行，比翻 30 个文件有用得多。而且「卡住的地方」这一行会稳定暴露你的真实薄弱点——连续三天都卡在同一类事情上，那就是你必须回头补的概念。

6 · 每日定量节奏

动作时长说明
热身（跑旧代码）~10′从 snippets 随机挑 1–2 个，不看源文件重写
看视频（2 倍速）~60′按上一节选模式，不是全程跟着敲
精写程序~50′最多 3 个，每个都写「为什么」注释
三行日志~3′今天的新事 / 卡住的地方 / 一句话总结

两个反直觉但必须守的规矩：

① 一天不要写超过 3 个新程序。超过就是无效重复。一个程序如果在三天后能被你重新写出来，它的价值大于你新写三个程序。

② 别一天看超过 15 集。看视频是最容易产生「我在进步」错觉的活动，因为它不费力。（注：考前冲刺期这条不适用，见第 7 节）

7 · 明天 10/16（考前最后一天）特殊版

考试前一天不适合再用模式 1 了——它太慢，而且此刻你的目标已经不是「学新东西」，是「提取流畅度」。

明天全部切到「蒙写」：

  1. 把笔记里的三道模板（能被 3 整除的数 / 读到 0 为止统计 / 友好数）看一遍。
  2. 合上所有东西，从空白文件开始写。不看笔记，不看视频，不看你的 snippets。
  3. 卡住的地方就是明天唯一的复习清单。只有这些地方值得回去看。
  4. 剩下的时间拿来再蒙写一遍。重复这一轮，直到三道都能在 10 分钟内写出来。

而且要分散到不同时间段：上午蒙写一遍 → 下午蒙写一遍 → 晚上蒙写一遍。集中在晚上连写三遍等于一遍。

8 · 这套怎么扩展到其他科目

你说要「可扩展」，那把通则抽出来——这四个动作不挑语言、不挑科目：

  1. 任何输入型学习，都必须在 24 小时内转成一次输出。这是整套方法唯一的核心。看视频、看书、听课——当天不做一次提取，等于白看。
  2. 间隔 > 次数。隔天做第二遍，胜过当天做三遍。这一条适用于所有记忆类任务。
  3. 写「为什么」不写「是什么」。笔记、注释、错题本，全部按这个标准。
  4. 卡住的那一下，才是学习的时刻。顺畅地抄完 20 行，脑子里什么都没留下；卡住 5 分钟然后想通，这一段跟了你一辈子。
场景怎么套
数据结构（大二）同一个链表，今天写 malloc 版 → 明天凭记忆写一遍 → 后天加个「无头结点」的变体做改动测试
学第二门语言
Python / Java		新语法用模式 1（先猜再验证）；你已经会的概念迁移过来时用模式 3（找个 C 程序改写成新语言）
数学就是你已经有的「定义优先法 + 一题三遍」——同构
英语就是「检索练习」——背单词不如合上书默写，同构

你现在已经把这个原则见了三遍了——数学的默写定义、英语的检索练习、C 语言的延迟复现。它们不是三个技巧，是同一条规律。以后遇到任何「学了记不住」的情况，先问一句：「我在 24 小时内做过一次输出吗？」答案基本就是原因。
